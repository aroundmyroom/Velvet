# v0.4.29 — Diacritic Folding in Similar-Artist Matching

Auto-DJ's Similar Artists mode no longer silently drops artists whose accented spelling differs between Last.fm and your library tags.

## The problem

Last.fm returns canonical artist names — often with diacritics ("Tiësto", "Beyoncé", "André Hazes"). If your library tags spell the same artist without them (or the other way around), the name lookup failed and that artist was quietly excluded from the Auto-DJ candidate pool. No error, no fallback — the artist just never played.

This is not a fringe case: a typical library holds hundreds of artists with non-ASCII names, plus sneakier variants like curly apostrophes ("Alexander O'Neal" vs "Alexander O’Neal") and Unicode hyphens ("All-4-One" vs "All‐4‐One") that look identical on screen but never match byte-for-byte.

## The fix

`resolveArtistNamesForDJ()` gained a third matching tier on top of the existing exact and `&`↔`and` normalized tiers:

- **Unicode NFD folding** strips combining accents: é→e, ö→o, ü→u, ñ→n
- A small fold map covers letters NFD cannot decompose: ø, æ, ß, đ, ł, ð, þ
- Typographic punctuation is folded too: curly apostrophes → straight, all Unicode hyphen variants → `-`

The folded tier is **unioned** with the other tiers rather than used as a fallback — if your library holds both "Alizée" and "Alizee" as separate artist rows, all variants merge into one candidate pool.

SQLite cannot fold diacritics natively, so matching runs JS-side against a lazily-built folded index over the normalized artists table, rebuilt automatically when the artist count changes after a scan.
