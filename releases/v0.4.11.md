# v0.4.11

Fix: `bitRate` in song metadata incorrectly showed the transcoded target bitrate instead of the source file's actual bitrate.

## Fixed: `bitRate` field overwritten with transcoded bitrate

v0.4.6 changed `buildSong` to replace `bitRate` with the configured transcode default (e.g. 192 kbps) whenever `transcodedSuffix` was set. Per the OpenSubsonic spec, `bitRate` represents the source file's bitrate — not the transcoded stream's bitrate.

This caused clients like Tempus to display the wrong bitrate when playing in passthrough mode (e.g. on Wi-Fi where the original FLAC is served directly): the file is 800 kbps but the metadata said 192 kbps, so 192 was displayed regardless of whether transcoding was actually happening.

`bitRate` now always reflects the source file's actual bitrate. The `transcodedSuffix` and `transcodedContentType` fields remain as the correct OpenSubsonic-spec indicators that transcoding is available.
