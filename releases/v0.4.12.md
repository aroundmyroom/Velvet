# v0.4.12

Fix: Symfonium library appeared completely empty and tracks were unplayable when `transcode.enabled: true` in Docker.

## Fixed: `transcodedSuffix` in song metadata causes Symfonium to route playback through extension endpoints that fail in Docker

When transcoding was enabled, every song in `buildSong` included `transcodedSuffix` and `transcodedContentType` fields. Symfonium uses these fields to decide whether to use the `getTranscodeDecision` / `getTranscodeStream` extension flow — regardless of whether the `transcoding` extension is advertised in `getOpenSubsonicExtensions`.

In Docker environments, `getTranscodeStream` fails due to file path differences between the host and container, causing Symfonium to report "no media to play" for every track. The Albums/Artists views appeared completely empty because Symfonium treats tracks with no working playback stream as non-existent in those views. Folder browsing showed the tracks but playback still failed.

**Fix:** `transcodedSuffix` and `transcodedContentType` are removed from `buildSong`. The `stream` endpoint already correctly handles `format` and `maxBitRate` parameters — both Symfonium and Tempus work correctly via the standard transcoding params without needing metadata hints. The `getTranscodeDecision` and `getTranscodeStream` endpoints remain available for clients that call them explicitly.
