# Velvet v0.2.8 — Docker: PUID/PGID support and permission safeguard

## Docker — PUID / PGID support

The container now accepts `PUID` and `PGID` environment variables, following
the LinuxServer.io convention:

```yaml
environment:
  PUID: 1000   # uid of the host user who owns the mounted folders
  PGID: 1000   # gid of that user (run `id` on the host to check)
```

When the container starts as root the entrypoint reassigns its internal `node`
user to those ids before dropping privileges — so the process reads and writes
files as the same uid that owns your bind-mounts. No `user:` override in
Compose is needed or recommended.

**Also fixed:** the writable-dir check incorrectly included `/app/bin`, an
internal container path that is never bind-mounted. This caused containers
started with a `user:` Compose override to exit 70 even when all real data
directories were writable. That false alarm is now gone.

## Album-Art Workshop — actionable error on permission failure

Applying a cover image to an album folder that isn't writable previously
surfaced as a silent HTTP 500 with no usable detail. It now returns a clear
error message naming the folder, the uid the process is running as, and the
fix to apply (`chown` or `PUID`/`PGID`).
