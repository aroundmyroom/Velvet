# Velvet v0.5.23 — Queue Search, Gentler Sonos Recovery, Cede Fix

Three changes: a new feature, and two more fixes in this week's Sonos work.

## Search the queue

A search box under "Up Next" finds a song already in a large queue. Type an
artist or title and every match is highlighted in place — a gold marker and
underlined matched text — while the rest of the queue stays visible and in
order, since a queue's order is part of what it tells you. The list jumps to
the first match automatically. Click a highlighted row to play it, same as
any other row. Case- and accent-insensitive. Desktop/tablet player only for
now. See `docs/queue-search.md`.

## Sonos recovers more gently, and the server log shows its actual commands

If a Sonos stream dropped, the player used to jump straight to rebuilding the
whole queue to recover — audible as a brief restart. It now tries a plain
"resume playback" command first, which doesn't touch the queue at all; most
transient hiccups should now resolve silently. The full rebuild is still
there as a fallback if that doesn't work within a few tries.

Separately, the server log now shows the actual commands sent to a Sonos
speaker — which action, to which device, with which file or setting — not
just summaries of the outcome. Failures are logged too, even for commands the
player doesn't wait on.

## Picking a song while Sonos had taken over silently did nothing

Selecting a song to play could update the player's own display while never
reaching the Sonos speaker at all, with no error shown — the speaker kept
playing whatever it had before. This was a side effect of yesterday's
protection against the player fighting a genuine handover to the Sonos app:
it also blocked the one action that should always be able to take control
back — explicitly choosing a song, exactly like pressing Play already does.

Picking a song now always reaches the speaker.

## Upgrade note

Restart the server after upgrading, and reload the player in your browser to
pick up all three changes.
