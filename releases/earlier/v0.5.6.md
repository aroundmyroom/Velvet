# Velvet v0.5.6 — Restore Client Scrobbling

This compatibility release restores Last.fm and ListenBrainz scrobbling for
third-party Subsonic and OpenSubsonic clients such as Tempus and Naviamp.

## What was happening

Velvet advertised the newer OpenSubsonic `playbackReport` extension. Some
clients preferred that timeline endpoint over the classic Subsonic `scrobble`
endpoint while sending `ignoreScrobble=true`. Velvet correctly honoured that
flag, but the result was that client playback no longer updated play counts or
forwarded completed listens to Last.fm and ListenBrainz.

The server settings and linked accounts remained valid; the playback events
were being suppressed before they reached the shared scrobble path.

## What changed

Velvet no longer advertises `playbackReport`, directing compatible clients back
to the proven classic `scrobble` endpoint. The `reportPlayback` endpoint remains
available for explicit callers and continues to honour `ignoreScrobble`.

Client playback once again updates:

- Last.fm scrobbles
- ListenBrainz listens
- Velvet play counts and Recently Played
- Play History and Wrapped statistics
- Auto-DJ listening history

Regression coverage now verifies both the advertised extension set and repeated
classic client scrobble submissions.

## Upgrade note

Restart the server after upgrading. Some clients cache server capabilities, so
refresh or reconnect the Velvet server entry in Tempus, Naviamp, or another
client before testing a complete track.
