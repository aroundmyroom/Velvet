# v0.4.8

Fix: transcoding admin panel shows "Not ready" even when FFmpeg is already installed (e.g. in Docker).

## Fixed: FFmpeg status always "Not ready" until user clicks Verify/Download

The server previously only probed for the FFmpeg binary at startup when `transcode.enabled` was `true`. With transcoding disabled (the default), the binary was never verified, so `isDownloaded()` returned `false` and the admin panel showed "Not ready" — even in Docker where the binary is pre-bundled and fully present on disk.

The user had to manually click "Verify / Download" to get the correct status, which was confusing: the button implied FFmpeg needed to be downloaded even though it was already there.

The fix: the binary probe now always runs on startup regardless of the `enabled` flag. If FFmpeg is present, the status shows "Ready" as soon as the Transcoding panel is opened. If the binary is absent, the status remains "Not ready" as before.
