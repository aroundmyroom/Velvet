# Velvet v0.7.0 — NFS/SMB now actually works on unprivileged containers

A real fix to the Proxmox LXC / Incus install wizard, reported live:
`mount.nfs: Operation not permitted` on an unprivileged container, even
with the mount feature correctly enabled. Privileged worked.

## What was actually wrong

Researched this one properly rather than patching on another guess — it's
the third attempt at the same underlying problem, and that was reason
enough to stop and check it thoroughly instead. Confirmed across multiple
independent sources: **NFS and CIFS cannot be mounted directly inside an
unprivileged container at all.** It isn't an AppArmor restriction the
`mount=nfs`/`mount=cifs` container feature can unblock — the kernel's own
client code for both filesystems has no support for the user-namespace
mechanism unprivileged containers depend on. That feature flag was correct
and is still needed, for privileged containers; it was never going to be
enough on its own for unprivileged ones, no matter how correctly it was
set.

## The fix

Mount the share on the Proxmox or Incus **host** instead, then give the
container the same kind of bind mount the local-folder option already uses
— the fix every source consistently pointed to. Nothing changes about how
the wizard is used: the same three options, same questions. On an
unprivileged container (the default), this now just happens automatically
behind the scenes. SMB mounts set up this way use the UID mapping a default
unprivileged container expects, so files written from inside the container
come out owned correctly on the host side.

[`docs/lxc-incus.md`](../docs/lxc-incus.md) has been substantially rewritten
to match, including correcting an earlier claim — that NFS/SMB shares don't
have the permission considerations local folders do — that this exact
investigation disproved.

## Also: a plain-language heads-up at the point of choice

Right after picking NFS or SMB, before any server details are asked for,
the wizard now explains what's about to happen: privileged mounts inside
the container, unprivileged mounts on the host instead automatically,
either way the host itself needs network access to the share, and for SMB
that the password goes into a root-only file rather than anywhere Velvet's
own configuration would read it.

## Verified

Shellcheck and syntax checks are clean, and the full suite still passes at
304 of 304. The host-mount path itself needs a real unprivileged Proxmox or
Incus host to confirm end to end — the same caveat as the rest of this
install path.
