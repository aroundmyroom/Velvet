# Velvet v0.2.2 — Player experience — accessibility, design system, queue multi-select, and stability fixes

A broad player improvement release shipping four independent workstreams alongside two
stability fixes.

## Accessibility (Wave 6)

- **Screen-reader track announcements.** A polite ARIA live region announces *"Now
  playing: \<title\> — \<artist\>"* on every track change so screen-reader users
  hear what started without hunting the now-playing bar.
- **WCAG AA contrast.** Secondary and tertiary text colours (`--t2`/`--t3`) were
  nudged lighter across the Velvet, Dark, and Light themes; every normal-text pair
  now clears the 4.5:1 AA threshold.
- **High-contrast theme.** Pure black/white palette, AAA-level contrast, bright
  focus ring. Suitable for low-vision users.
- **Colorblind-safe theme.** Blue/orange palette — no red↔green distinctions.
- **Fixed: theme switcher was unreadable in High-contrast.** The segmented pill used
  `--border` as its track fill; High-contrast sets that to white, making the pill
  disappear. Now uses a dark track with white outline and labels.
- **Fixed: High-contrast and Colorblind themes broke the responsive layout.** They
  redeclared `--qp-width`/`--sidebar` but were missing from the breakpoint rules,
  locking panels at desktop width on narrow screens.

## Design system — foundation (Wave 5)

- **Spacing and type-scale tokens.** `--sp-1` → `--sp-8` (4 px → 64 px) and
  `--type-xs` → `--type-2xl` (11 px → 28 px) are now defined and adopted across the
  sidebar, player bar, and queue panel.
- **Button class system.** `.btn`, `.btn-primary`, `.btn-ghost`, `.btn-danger`,
  `.btn-icon` — consistent `:focus-visible` ring and `disabled` states throughout.
- **SVG icon helper.** `icon(name)` returns named SVG strings for the six
  most-repeated shapes, replacing repeated inline literals in the four song-row
  renderers.

## Queue multi-select (Wave 3c-ii)

- **Click the position number to select; click the row to play.** The left-side
  number cell is now a dedicated select zone — no more accidental playback when
  you want a checkmark.
- **Ctrl/Cmd+click to select, Shift+click to range-select.** Selection state lives
  only in a JS Set so it survives virtual-scroll row recycling correctly.
- **Selection bar with bulk actions.** When ≥1 items are selected a compact bar
  appears above the queue list: item count, **Remove** (deletes selected tracks,
  adjusts the current-song pointer), **Add to playlist** (bulk-adds all selected
  songs via the existing playlist picker).
- **Escape clears the selection.**
- **Fixed: selection stopped working after logout → login.** A second click handler
  was registered on `#queue-list` on every login (logout does not reload the page),
  causing each click to toggle on then immediately off. A one-per-page-load guard
  prevents re-registration.

## Stability fixes

- **Fixed: browser-cached `index.html` could hide new DOM features.** `index.html`
  was served without a `Cache-Control` header, so browsers applied heuristic caching.
  New JS/CSS loaded fine (they have content-hash cache-busters) but new HTML elements
  — like the queue selection bar — were silently absent. Now served with
  `Cache-Control: no-cache`.
- **Fixed: Auto-DJ `QuotaExceededError` stopped next-song picks.** Two localStorage
  bloat sources filled the 5 MB quota: accumulated `wf:` waveform keys (~2 KB each,
  growing forever) and oversized artist-history strings. Fix: the `wf:` localStorage
  layer is removed entirely — waveforms are cached server-side and in a session
  `Map`; artist history is capped at 500 entries with a self-healing fallback. A
  one-time startup migration clears existing bloat for every user.

## Upgrade notes

No action required. The one-time localStorage migration runs automatically on first
page load.
