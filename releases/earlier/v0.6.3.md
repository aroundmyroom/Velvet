# Velvet v0.6.3 — Proxmox LXC / Incus: NFS and SMB shares, and a cleaner wizard

A redesign of v0.6.1's container-creation wizard, based on real feedback
after trying it: the questions it asked before the container existed looked
bolted-on, had no explanation, offered no network-share option, and the one
password field had no confirmation.

## One question, not five

Checked against real install scripts from the community-scripts catalog —
PiHole, Immich, n8n, WG-Easy — and none of them ask for app configuration in
the container-creation script at all. That settled it: the admin-account and
extra-library-folder questions the wizard used to ask are gone. Velvet
already starts in open mode with nothing configured, exactly like a plain
`docker run` with no options, and everything is set up from its own admin UI
once it's running. There was nothing in those two questions that actually
needed asking before the container existed.

## The one question that's left, done properly

Where the music library lives is kept, because it's the one real exception —
it decides what gets attached to the container at creation time, which can't
be changed from inside the app afterward. It's now a `whiptail` menu matching
the look of the rest of the wizard (a coloured plain-text menu on hosts
without `whiptail`), with three options:

- **A local folder on this host** — bind-mounted in, the original option.
- **An NFS share** (`server:/export/path`) — mounted inside the container
  itself, with a mount-options prompt.
- **An SMB/CIFS share** (`//server/share`) — username and password, blank
  username for guest access. The password is asked twice and must match
  before continuing, retried up to three times, and pushed into the
  container as a credentials file rather than ever appearing in a command.

Unlike a local bind mount, NFS and SMB shares are mounted by the container
itself as its own user, so they sidestep the unprivileged-container
UID-remapping issue entirely — one real reason to prefer a network share
over a bind mount when both are available.

## Two real bugs, found by testing, not by reading

Verifying the new wizard meant actually scripting answers through its logic
in an isolated test harness, not just reading it — and that caught two
things reading the code alone hadn't:

- The plain-text fallback's explanatory menu lines were going to the same
  output stream the script captures to read back the chosen answer, so the
  whole menu text ended up glued onto it.
- "Leave blank to skip" on the local-folder prompt silently didn't work — a
  default value got substituted in instead — and because that default
  directory doesn't exist on a fresh host, the retry loop had no way out and
  could hang indefinitely. The identical mistake also prepended a stray
  newline to every SMB password entered this way, which would have broken
  the credentials file for anyone who set one.

Both are fixed. Every retry loop in the wizard is now capped with a clear
path to skip rather than looping forever.

## Status

[`docs/lxc-incus.md`](../docs/lxc-incus.md) is updated to match. The prompt
and validation logic has real test coverage now (an isolated harness
exercising every input path). The container-creation and mount steps
themselves still need a real Proxmox VE or Incus host to verify end to end —
that part is unchanged from v0.6.1.
