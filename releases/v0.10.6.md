# Velvet v0.10.6 — Sendspin spec update and dependency updates

## Safer pairing with a six-digit code

The Sendspin specification now requires a server to warn you before you
type a code that a speaker shows or reads out. When you pair a speaker
with a six-digit code under **Admin panel → Rooms**, Velvet now tells you
to start pairing on the speaker itself first (its button or app), and not
to trust a code the speaker shows without that step. Another server on your
network could otherwise make the speaker show its own code. The text is in
all 12 languages, and `docs/rooms.md` explains it too.

## Still up to date with Sendspin

Velvet Rooms was checked against the latest Sendspin specification and the
latest reference clients:

- Against the aiosendspin client every scenario it can run passes (14 of
  15; that client has no Opus).
- Against the sendspin-js client, Opus streaming now passes as well.
- The rules the reference server adopted in the past weeks (name and
  metadata length limits, group ID format, streams only during playback)
  were already met.
