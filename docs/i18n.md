# Internationalisation (i18n)

Velvet ships a full runtime i18n system for both player and admin.
Language switching is instant and does not require a page reload.

---

## Engine

Core file: `webapp/assets/js/i18n.js`

It exposes a global `I18N` object (also `window.I18N`) plus a `window.t` alias.

| API | Description |
|-----|-------------|
| `I18N.t(key, params?)` | Translate key with fallback to English, then to the key itself. Supports `{{param}}` interpolation and plural objects (`{ one, other }` with `count`). |
| `I18N.loadLanguage(lang?)` | Load a locale (or auto-detect from localStorage / browser language). |
| `I18N.getLanguage()` | Return current language code. |
| `I18N.onChange(fn)` | Subscribe to language changes (returns unsubscribe). |
| `I18N.ready` | Promise that resolves after initial language load. |
| `I18N.translatePage()` | Apply translations to `[data-i18n]` DOM nodes. |
| `I18N.listLanguages()` | Return supported language metadata (label, flag, country) for UI pickers. |
| `I18N.setUser(username)` | Switch to the per-user language key after login. |

Language preference is stored in localStorage: `velvet-lang_<username>` when a
user is known, with `velvet-lang` kept as the global fallback. Downloaded locale
files are cached as `velvet-locale-<code>` (plus `velvet-locale-hash-<code>`);
the cached copy is used when the network fails.

---

## Safety and sync behavior

- Locale JSON is validated before activation.
- Invalid or unloadable locale files are rejected.
- On failure, UI stays on the previous valid language and shows a visible error.
- Open tabs synchronize language changes through `storage` events on `velvet-lang` and `velvet-lang_<username>`.

---

## Language availability control

- Public endpoint `GET /api/v1/languages/enabled` exposes enabled language codes.
- Admin endpoints (stored in the config as `languages.enabled`):
  - `GET /api/v1/admin/languages/config`
  - `POST /api/v1/admin/languages/config` — body `{ enabled: [...] }`
- Player and admin pickers only render enabled languages.
- English (`en`) is always kept enabled as fallback baseline.

---

## Locale files

All locale dictionaries live in `webapp/locales/` (12 languages) and must stay key-synchronized:

- `en.json` (authoritative source)
- `nl.json` (Dutch)
- `de.json`, `fr.json`, `es.json`, `it.json`, `pt.json`, `pl.json`, `ru.json`, `zh.json`, `ja.json`, `ko.json` — mostly translated; keys that are not translated yet carry the English text
- `languages.json` — code → display name list

Each locale has about 3,700 flat keys: ~2,200 `admin.*`, ~1,300 `player.*`,
and a small set of older top-level keys (`nav.*`, `upload.*`, `metadata.*`, …).

CI checks key parity on every PR: the `locale-sync` job runs
`node scripts/locale-parity.cjs`, which fails when any locale misses a key from `en.json`.

---

## UI behavior

- Player and admin use compact flag-button language pickers.
- Pickers show real country flag icons and an emoji fallback when image loading fails.
- Active language is highlighted and updates reactively.
- Static markup updates through `data-i18n` scanning after each successful language load.
- Player screens rendered from JavaScript template strings must subscribe to `I18N.onChange(...)` and rebuild the active view so open panels switch language immediately without navigation.
- The player re-renders the current dynamic view on language change for top-level screens plus stateful views such as File Explorer, Search, saved playlists, smart-playlist results, Auto-DJ, Playback, and podcast episode lists.

## Other web apps

The smaller apps load the same engine (`/assets/js/i18n.js`) and the same locale files, each with its own key prefix:

| App | Keys |
|-----|------|
| Mobile web app (`webapp/mobile/`) | `mobile.*` |
| Samsung TV app (`webapp/tizen/`) | `tizen.*` — the app is installed on the TV, so it loads the engine and locale files from the Velvet server it connects to |
| Server Remote (`webapp/server-remote/`) | `server-remote.*` |
| Shared-playlist page (`webapp/shared/`) | `shared-page.*` (also its expired / not-found error page) |

All of them are translated: static text through `data-i18n`, text built in JavaScript through `t()`.

---

## Translation rules

- Never hardcode user-visible text in templates or JS.
- Use i18n keys:
  - player: `t('player.*')`
  - admin: `this.t('admin.*')`
  - static HTML: `data-i18n="..."`
- Add new keys to `en.json` and `nl.json`, then sync all remaining locales.

## Admin panel

The admin panel (`webapp/admin/index.js`, Vue 2) uses `admin.*` keys. The first
panels were converted later (About, Telemetry, Server Audio, Transcode,
Database, Genre Groups, Artists, Scan Errors); every panel built since uses
keys from the start.

- Use `t('admin.section.key')` in templates and `this.t(...)` in component code.
  `t()` is defined once on `Vue.prototype` (it calls `I18N.t` and depends on the
  reactive language tick). Never define a `t()` method inside a component — that
  hides the prototype and shows raw keys instead of text.
- Keep reusable labels under `admin.common.*` (`enable`, `disable`, `yes`, `no`, …).
- For dynamic strings, use params (example: `admin.serverAudio.detectFound` with `{{version}}` and `{{path}}`).
- The admin language picker shows only the languages from `/api/v1/languages/enabled`, like the player.
- The file-explorer modal uses the `admin.modal.browse*` keys.
- The player shell bootstrap lives outside inline HTML scripts so manifest and locale-picker boot code run without inline-script CSP violations. (The `/admin` route and the player entry routes allow route-scoped `unsafe-eval` — Vue 2's template compiler and Butterchurn preset compilation both need it.)
