# v0.4.16

Fix slow track start / retry loop and wrong format display in Tempus; add two missing Server Speaker endpoints.

## Fixed: Transcoded stream caused 3× retry loop and slow playback start in Tempus

The CBR `Content-Length` estimate added in v0.4.14 conflicted with `TranscodingMediaSource` (activated via `transcodeOffset` in v0.4.15). That client probes the stream before committing, and since libopus is VBR the actual byte count never matched the estimate — ExoPlayer treated it as a truncated response and retried, adding 4–7 s of latency per track and sometimes requiring a second manual Play press. `Content-Length` is now removed from transcoded streams; `TranscodingMediaSource` derives duration from the `getSong` `duration` field instead.

## Fixed: Tempus displayed "FLAC 800kbps" instead of actual transcode output format

`buildSong` reported the source file's `suffix` / `bitRate` regardless of server-side transcoding. Tempus (and other OpenSubsonic clients) showed "FLAC 800kbps" while streaming Opus. For lossless source formats (flac, wav, aiff, ape, wv, wma, alac…) Velvet now populates `transcodedSuffix` and `transcodedContentType` when transcoding is enabled, so clients correctly display the output codec (e.g. "Opus 192kbps").

## Added: Missing Server Speaker API endpoints

Two endpoints documented in the API reference since v0.4.x but never implemented:

- `POST /api/v1/server-playback/queue/add-many` — append multiple files to the queue in one call, returns `{ indices }`.
- `POST /api/v1/server-playback/play` — convenience shortcut: clear queue, add one file, start playback.
