# Velvet v0.6.9 — Fix an unkillable hang right after choosing NFS/SMB

A critical fix to the Proxmox LXC install wizard, reported live: right after
confirming NFS or SMB mount support, the install would freeze completely.
An animated spinner stayed stuck on screen, Ctrl-C did nothing, and the
only way out was closing the terminal entirely.

## What was happening

The engine this wizard runs on shows progress with an animated spinner:
one call starts it, and a separate follow-up call is what stops it. The
message confirming NFS or SMB mount support started that spinner but never
stopped it, and the very next thing the wizard does is open the
container-creation dialog screen.

That left two things fighting for the same terminal at once. The dialog
screen takes over keyboard input directly, so the stuck spinner's keystrokes
never had anywhere to go — which is exactly why Ctrl-C appeared to do
nothing. It wasn't ignored, it just wasn't reaching anything that would act
on it.

## What's fixed

Added the missing stop to both the NFS and SMB confirmation messages, so
the spinner ends cleanly before the dialog screen opens.

While tracking this down, every other place in the script using this same
spinner pattern was checked by hand against the identical failure mode. One
more gap turned up, in the step that installs NFS/SMB client tools on the
host to test a share before creating the container — harmless in practice,
since the code that calls it already stopped the spinner itself a few lines
later, but fixed for correctness regardless, and the fix also removed a
redundant duplicate error message along the way.

## Verified

Shellcheck and syntax checks are clean, and the full test suite still
passes at 304 of 304. The exact terminal interaction that caused the freeze
can't be reproduced outside a real interactive session, but the cause
itself isn't a guess — it was confirmed directly from the engine's own
spinner implementation, not inferred from symptoms alone.
