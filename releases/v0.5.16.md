# Velvet v0.5.16 — Network Recovery Seek Fix

A follow-up fix, separate from yesterday's Sonos cede fix (v0.5.15).

## Unexpected stops and starts while casting

If you were casting to a Sonos speaker or the Server Speaker output and left the
browser tab in the background, you may have heard the audio briefly stop and
restart on its own, with no seek or skip intended.

The cause: browsers slow down background tabs, which made the player's stream
stall and recover more often. Each time it recovered, it resumed its own internal
clock at the position it had reached — and that resume was mistakenly treated
the same as the listener deliberately dragging the seek bar, and sent straight to
the active speaker as a real position change. A live seek like that can briefly
stall a speaker or restart a track, which is exactly what was being heard.

Recovering from a stall no longer sends anything to Sonos or the Server Speaker —
it only catches the player's own display up to where the stream actually is.

## Upgrade note

Restart the server after upgrading, and reload the player in your browser to pick
up the fix. This is most noticeable if you regularly leave the tab in the
background while casting, so it is worth testing with a track left playing that
way for a few minutes.
