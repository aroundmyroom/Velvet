# Velvet v0.6.5 — Fix a live crash on Cancel in the Proxmox LXC / Incus wizard

Reported from a real Proxmox run: cancelling the music-library dialog in
v0.6.4's install wizard crashed the whole installer instead of skipping
gracefully, with `exit code 1 (General error / Operation not permitted)`.

## What was wrong

The wizard uses `whiptail` for its dialogs, which exits with a non-zero
code when a dialog is cancelled — that's by design, not an error. The
underlying community-scripts engine runs every app script under strict
error handling, where any unguarded non-zero exit is treated as fatal
immediately. Two of the wizard's dialogs had no guard against that
particular, expected kind of "failure," so a cancel was read as a crash
rather than the "skip this" it was meant to be.

## What's fixed

- Both `whiptail` menus (the music-library choice, and the "what now" menu
  after a failed share test) now resolve to "skip" when cancelled, instead
  of aborting the script.
- A related issue in the SMB/CIFS test code: it captured a command's exit
  status in a way that wasn't protected against the same strict error
  handling, so a failed test could have hit the identical crash one step
  later. Fixed.
- All four places the wizard reads a typed answer got the same defensive
  treatment, in case the input stream ever closes unexpectedly.

## How it was verified

By reproducing the exact crash, not by reading the code again. A
scriptable stand-in for `whiptail` — one that behaves like the real thing,
including on Cancel — drove the actual, unmodified wizard logic through
every dialog being cancelled, under the same strict error handling the real
engine applies. It now resolves cleanly every time instead of aborting. The
plain-text fallback path (for hosts without `whiptail`) was verified the
same way through a real pseudo-terminal, covering the SMB password-retry
and share-test-retry flows together under the identical conditions.

[`docs/lxc-incus.md`](../docs/lxc-incus.md) now documents that cancelling
any dialog in the wizard always means "skip" — it never crashes the
installer.

## Still open

The "2x 404" also reported alongside this crash is not yet diagnosed — it
needs the actual log lines to track down, which haven't been provided yet.
