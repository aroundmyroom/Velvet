# Velvet v0.5.29 — Sonos End-of-Track Fix, Auto-DJ in the Server Log

Four fixes and one addition, all of them found by reading the server log
against what was actually heard: Sonos going silent at the end of a track, a
track Sonos would never accept, an Auto-DJ pick that made no sense, and the
fact that the log could not explain any of the three until now.

## Sonos went silent at the end of a track — and replayed it instead of moving on

The speaker would finish a track and just stop. No next track. When the
browser tab came back into view, the *same* song started again from the
middle. This happened for a whole morning, with the browser open and only the
tab in the background.

Since v0.5.25 the web player's own muted playback is the single clock that
decides when a track is over — Sonos is told the next track when the browser
reaches the end. That is fine as long as the browser's clock runs in real
time. It did not: casting silences the browser through the audio graph (a
gain of zero, so the VU meters keep working) rather than muting the element,
and a graph producing pure silence lets Chromium close the real audio device
and run the graph from a timer — which lags in a background tab and takes the
playback clock with it. Meanwhile the speaker streams the file straight from
the server and reaches the end regardless. The old self-heal then read the
speaker's "stopped" as a dropped stream and re-cast the track from the stale
position.

Three things changed:

- An inaudible keep-alive signal keeps the audio device open while casting, so
  the browser's clock runs in real time again.
- The heartbeat now checks the wall clock: if the speaker is stopped and, since
  the cast, it has had the whole track's worth of real time, it finished —
  Velvet advances to the next track exactly as it would at the natural end. A
  stop *before* that point is still treated as a dropped stream and re-cast.
- If the browser's clock ever falls behind anyway, the log says so
  (`local mirror lagging: advanced 4s in 30s of wall clock`), and the next cast's
  log line carries the reason
  (`cast-queue ▶ … (speaker finished the previous track; web player clock was at 2:55/4:54)`).

## One track Sonos refused to play at all

A WAV whose album tag held stray control characters — a mangled "2 × Vinyl,
33 ⅓ RPM" — could not be cast: the speaker rejected every attempt with UPnP
error 402 and the player retried on each seek. The metadata Velvet sends is
XML, and those characters are not allowed in XML, so the whole document was
invalid. Characters XML forbids are now stripped before the metadata is built,
as the DLNA server already did; the track casts, and the rest of the tag text
shows as-is.

## Auto-DJ jumped from a dance run to 80s Italo

A track credited as "Martin Solveig Fe. Roy Woods" got zero similar artists
from Last.fm, because "Fe." was not one of the separators Velvet recognised
(feat./ft./featuring/vs./pres./x) and so no fallback to "Martin Solveig" was
ever tried. With no similar-artist signal, that one pick was made on BPM, key,
era and genre alone across the whole collection. 384 artist credits in one
real library use this shorthand. "Fe." is now recognised, and a track number
that leaked into the artist tag ("12. Joel Corry Fe. MNEK") is stripped before
the lookup as well.

## Auto-DJ decisions in the server log

`journalctl -fu music.service` now shows *why* Auto-DJ picked what it picked,
without the browser console: one line for the Last.fm similar-artist lookup
(what came back and via which part of the credit — or `→ 0 (tried: …)`), one
for the candidate pool (its scope and any fallback that widened it), and one
`[autodj] ▶` line when the pick starts playing — score, pool size, similar
artists in play, an active genre escape, and the BPM/key/year/genre change
from the previous track. Every field is capped and text is truncated, with no
candidate lists, so a full day of Auto-DJ is a few dozen KB of log.

## Upgrade note

Restart the server after upgrading, and **hard-refresh the web player** — the
Sonos end-of-track fix and the keep-alive live in the browser.
