# v0.4.14

Three Subsonic transcoding fixes for Tempus and ExoPlayer-based clients.

## Fixed: Opus `Content-Type` was `audio/ogg` instead of `audio/opus`

ffmpeg `-f opus` outputs a native Opus bitstream — not an OGG-wrapped container. Sending the wrong MIME type caused ExoPlayer to dispatch `OggExtractor` (which expects the `OggS` magic byte) instead of `OpusExtractor`, potentially causing parse failures or silence. Corrected to `audio/opus`.

## Fixed: Transcoded streams had no `Content-Length` — seekbar showed no duration

`pipeTranscodeToRes` pipes ffmpeg stdout directly, so no `Content-Length` was ever set on transcoded responses. ExoPlayer's `ProgressiveMediaSource` uses `Content-Length ÷ bitrate` to estimate stream duration for formats (like native Opus) that don't embed it in the container. Without it, `player.getDuration()` returns `C.TIME_UNSET` and clients like Tempus show no seekbar progress or track length.

The server now sets an estimated `Content-Length` before the transcode pipe: `ceil(bitrateKbps × 1000/8 × durationSec)`. This is a CBR estimate — accurate enough for ExoPlayer to compute a usable duration and render the seekbar.

## Fixed: Transcoded bitrate capped at 192k

`_mapMaxBitrateKbps` only stepped down through `[192, 128, 96, 64]`, silently serving 192k to any client requesting 256k or 320k. Tempus lets users configure per-network bitrate ceilings; requesting 256k or 320k now works. Both values added to the lookup array and to `bitrateSet` in `transcode.js`.
