# Velvet v0.6.0 — In-App Updates, Samsung TV Now Playing Matches the Album Art

Velvet can now update itself. A new **Server → Updates** page in the admin
area tells you when a release is out, shows you its notes so you can decide,
and — on installs where that is safe — fetches the release, installs changed
dependencies, restarts and comes back on the new version, with every step on
screen. That is why this is a 0.6: from here on, keeping Velvet current is a
button, not a shell session.

## See a new release the moment you open the admin area

The **Updates** item in the Server menu wears a red badge with the new version
number (`v0.6.1`, say) as soon as a newer GitHub release exists, so nobody has
to remember to go looking. The page itself shows the installed version next to
the latest release, when it was published, and that release's notes rendered
from GitHub. Reading the notes changes nothing. Updating is a separate,
explicitly confirmed step, and only an admin can see the page or press the
button.

## It checks that *this* install can update itself before offering to

Self-updaters usually fail halfway. Velvet's checks first and tells you what
to fix instead:

- a bare-metal git checkout pointed at the official repository;
- no local changes and no local commits (boot-stamped cache-buster files are
  recognised and ignored);
- the OS user Velvet actually runs as can write the application folder,
  `.git`, `package.json` and `node_modules` — the page names the user and,
  when it can't, the exact `chown -R <user> <folder>` to run;
- npm available next to the running node (or on PATH);
- what will bring Velvet back after it exits: systemd, pm2, or nothing.

Each line shows a ✓ or ✗ with the reason and the fix. The button only unlocks
when a newer release exists *and* every check passes.

## The update itself, with progress — npm included

The update does exactly what `docs/install.md` has always told you to do by
hand, in order: `git fetch`, fast-forward to the release tag (staying on your
branch, so a later manual `git pull` still works), `npm install --omit=dev`
only when the lockfile changed, verify the new version, then exit so
systemd or pm2 restart it — or, with no service manager, start a new copy of
itself. Every step's output, including npm's own, streams to the page as a
progress bar and live log, and the same lines go to the server log as
`[update] …`. The page then waits for the server to answer again on the new
version and reloads itself. If anything fails in the middle, the checkout is
rolled back to the previous version and Velvet keeps running on it.

## Docker: it tells you, then shows you the right way

Inside a container the application files belong to the image, so the page
never touches them. It still checks for and shows the new release and its
notes, then prints the `docker pull` / `docker compose up -d` commands for the
new image tag — or use Portainer, Dockhand or Watchtower as before.

Full details, including the restart table and troubleshooting, in
[`docs/updates.md`](../docs/updates.md). New admin-only endpoints
`GET /api/v1/admin/update/check`, `POST /api/v1/admin/update/start` and
`GET /api/v1/admin/update/status` are documented in `docs/API.md`.

## Samsung TV: Now Playing tints itself from the album art

The Tizen app's full-screen Now Playing background was a fixed purple gradient
for every track. It now samples the current album art's dominant colour and
tints the glow to match — the same extraction the desktop player already uses
for its "Dynamic accent colour" option; the TV was the one client still on a
static colour. Deliberately subtle (a dark, moody tint, not a bright wash) and
scoped to the Now Playing background only; D-pad focus colours and the rest of
the UI are unchanged.
