# Velvet v0.5.20 — Sonos False-Cede and Stuck-Track Fixes

Two more fixes in the same area as this week's earlier Sonos releases, both
identified directly from user-supplied browser console logs.

## A formatting mismatch could wrongly hand control back to the Sonos app

The player could sometimes conclude the Sonos app had taken over — freezing
its own display and restarting the track when Play was pressed — even though
Sonos itself hadn't done anything unusual. The cause: comparing what Sonos
reported it was playing against what the player expected sometimes compared
two representations of the exact same file that were formatted slightly
differently (one with a leading slash, one without). A strict comparison read
that as two different tracks.

This is the most directly confirmed fix of the week — a user-supplied console
log showed the exact mismatched pair side by side, proving they were the same
file. Both places this comparison happens now compare fairly.

## Casting to Sonos could go silent indefinitely on a broken file

If a track's file had gone missing from disk since the library was last
scanned, casting to Sonos could get stuck there with no sound and no recovery,
even with more tracks already queued up. The existing recovery only re-tried
the exact same file at the exact same position, which cannot help when the
file is genuinely gone, and depended on the browser tab actively re-attempting
that same file — something a backgrounded tab may not reliably keep doing.

If Sonos reports it's stopped on the expected track and stays that way for 45
seconds, the player now skips to the next track regardless of what the
browser tab itself is doing. The skipped file is reported for admin review,
the same way any other unplayable file already is.

This is a best-effort improvement, not a guarantee for every case: if the
browser tab is fully suspended by the operating system rather than merely
slowed down, none of its code can run to notice the problem at all. A
complete fix for that specific case would need to live on the server instead,
and has not been built.

## Upgrade note

Restart the server after upgrading, and reload the player in your browser to
pick up both fixes.
