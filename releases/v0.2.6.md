# Velvet v0.2.6 — Sonos casting: UI locked to the speaker, clean seeking

A Sonos casting reliability release. No new features.

## The progress bar no longer runs ahead of the speaker

When casting, the muted local audio element drives the UI clock but starts
instantly, while Sonos takes a moment to begin streaming — so the progress bar
and waveform used to sit permanently ahead of the actual sound.

A proper **lead-in** now pins the UI clock to the device's real position until
Sonos is actually streaming, then runs in lockstep. There's no permanent
head-offset and no backward jump when audio begins. The position poll briefly
speeds up (1 s) during this lead-in only; it stays at 3 s for the rest of the
track and never speeds up near a track's end. The natural track-to-next
transition, external-control hand-off, and stopped-stream self-heal are
unchanged.

## Seeking / fast-forwarding lands cleanly

When you scrubbed the progress bar, a position poll landing mid-seek could read
the device's old position and snap the UI back to where you started. The poll
now holds off its drift correction for a few seconds after a seek, so the bar
stays at the new position while the speaker catches up — no more jump-back.

## Upgrade notes

No action required. (A separate follow-up will improve seeking *into an
unbuffered part* of a track, where Sonos itself can stall or restart the
stream — that's a deeper streaming change and ships once verified on hardware.)
