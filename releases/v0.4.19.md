# v0.4.19 — Playing Now & FFmpeg Fixes

## What's new

### Playing Now: Replay Gain now shows DB-measured values

The Track Info panel previously showed "—" for Replay Gain on any track where the gain was measured by the Normalisation Workshop but never written back to the file's tags. It now uses the same priority chain as the playback engine: measured value → R128 → embedded tag → "—".

### Playing Now: Replay Gain value now matches the playbar badge

The playbar badge shows the effective applied gain (track gain + pre-gain offset). The Track Info panel was showing only the raw track gain, so if you had any pre-gain set in ReplayGain settings, the two numbers appeared inconsistent. They now always agree.

### Playing Now: Replay Gain updates after lazy-fetch

Tracks restored from a previous session start with no RG data; it was fetched asynchronously in the background. The playbar badge updated correctly, but the Playing Now panel was not re-rendered after the fetch completed. Fixed — the panel now refreshes automatically.

### Docker: FFmpeg "Not ready" on fresh container start — fixed

After pulling a new Docker image, the admin panel briefly showed FFmpeg as "Not ready" even though the binary ships pre-bundled in the image. This happened because the readiness flag is set by an async init task, and opening the admin panel a few seconds after boot could race with that task. The status check now falls back to a synchronous file existence check, so Docker users will always see "Ready" immediately.
