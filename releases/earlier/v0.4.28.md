# v0.4.28 — Auto-DJ Queue-End Fixes

Two fixes for how Auto-DJ behaves at the end of the queue: NEXT no longer jumps back to the first song, and skipping to a new DJ track is now instant.

## NEXT no longer wraps to song #1

With Auto-DJ enabled and **Repeat: All** also on, pressing **NEXT** on the last track in the queue jumped back to the first song instead of fetching a fresh Auto-DJ pick. The repeat-all wrap was evaluated before the Auto-DJ branch ever got a chance.

Auto-DJ now owns the end of the queue: when it is enabled and you're on the last track, NEXT always brings a fresh DJ pick. The repeat-all wrap only applies when Auto-DJ is off.

Shuffle is now also genuinely inactive while Auto-DJ drives — the player already displayed *"Shuffle: On — but inactive, Auto-DJ is on"*, but the NEXT button still picked a random queue position. Code and message now agree.

## Instant skips with Auto-DJ

Skipping to the next title with Auto-DJ enabled could take 5–6 seconds. The next DJ pick was only prefetched ~25–45 seconds before a track's natural end — a manual NEXT earlier than that had to run the entire pipeline (Last.fm similar-artists lookup, a 500-candidate metadata batch, client-side scoring) before anything played.

The prefetch now fires ~2 seconds after a track starts (whenever it is the last queue item), so the next DJ song is already queued by the time you skip — NEXT is an instant queue advance. This applies to both the normal play path and the crossfade/gapless handoff path; the near-end prefetch remains as a backstop.

## Upgrade note

Client-side only — a plain `git pull` (or pulling the new image tag) is enough. Hard-refresh the browser after upgrading.
