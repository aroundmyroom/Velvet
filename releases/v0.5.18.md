# Velvet v0.5.18 — Sonos Position Drift Fix

Another follow-up in the same area as this week's earlier Sonos fixes — this one
identified directly from a user-supplied browser console log, and likely explains
some of what the earlier fixes were chasing.

## The player could lose track of what Sonos was actually playing

Over a long Auto-DJ session, the player's queue is periodically trimmed from the
front so it doesn't grow without bound — normal, low-level housekeeping. The
player's own "which track am I on" pointer was correctly adjusted every time
that happened. A separate, similar piece of bookkeeping — where the Sonos
device's own queue starts within the player's queue — was not.

Every trim left that second value a little further out of alignment, and the
error accumulated the longer a session ran. Confirmed live: after a long
Auto-DJ session, the mismatch had grown to roughly 37 track positions.

This is very likely the real explanation behind some of the other Sonos
playback oddities fixed earlier this week — a mismatch like this produces the
exact same symptom (the speaker playing something the player didn't expect) as
the timing issues those fixes addressed, and there was no way to tell them
apart without a live report like this one.

## Also: the server wasn't picking up recent releases

Separately, and unrelated to the bug above: this server had been running
continuously since before yesterday's two releases, and had not been restarted.
The page itself is cached in memory and only refreshed on restart, so the
version shown in the browser lagged behind what was actually installed — the
underlying fixes were already active, only the visible version number was
stale. The server has been restarted to clear this up, and future releases
will include a restart so this doesn't happen again.

## Upgrade note

Restart the server after upgrading (now part of the standard release process),
and reload the player in your browser to pick up the fix.
