# Velvet v0.6.7 — Fix two real bugs reported from a live NFS install

Two fixes to the Proxmox LXC / Incus install wizard, both found from the
same real install.

## The music library wasn't configured after a successful mount

The NFS share mounted correctly at the OS level — `mount` and `df` showed
it fine — but Velvet itself showed no folder and no library at all.

The cause: the wizard started Velvet once, immediately after creating the
container, before the mount or the first-run environment file existed yet.
It then relied on a second restart, after the mount and environment were
set up, for Velvet's own first-run bootstrap to catch up and create the
library folder. That's one unnecessary moving part, and it's exactly where
this install went wrong.

Fixed by removing it rather than chasing the exact timing further: the
installer now installs Velvet without starting it. The wizard finishes
mounting the library and writing `/etc/velvet.env`, and only then starts
Velvet — once, already fully configured. That's the same guarantee a Docker
container gets from never starting without its environment already set.

## Admin → Folders → Browse failed with "Failed to get directory content"

The same install's server log showed:

```
Error: ENOENT: no such file or directory, scandir '/home/velvet'
```

The system user Velvet runs as never had a real home directory on disk, but
Linux's `useradd` still recorded `/home/velvet` as the account's home
directory regardless — that's standard behavior, not something the installer
was asking for. The admin UI's folder-browser defaults to the OS home
directory as its starting point when opened with no path yet, which is
exactly what led it to a directory that didn't exist.

Fixed: the installer now gives that user an explicit home directory that
actually exists (`/opt/velvet`, where Velvet itself lives).

## Not a bug

The same log also showed warnings like "metadata parse error (covers
skipped)" and "could not compress album art." Those are Velvet's own,
normal handling of specific music files with unusual or corrupt embedded
artwork — the track keeps playing, just without a cover. Unrelated to the
installer, not something this release touches.

## Verified

Both fixes have new automated test coverage in
`test/integration/contrib-lxc-installer.test.cjs`. Full suite: 304 of 304.
