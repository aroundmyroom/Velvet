# v0.4.7

Fix `getTranscodeDecision` ignoring `maxAudioBitrate` — Symfonium was getting `canDirectPlay: true` for FLAC files even when the bitrate cap was set to 192 kbps.

## Fixed: `getTranscodeDecision` does not enforce `maxAudioBitrate`

The `ClientInfo` body from Symfonium (and other clients) includes a `maxAudioBitrate` field (bits/sec) that caps what the client is willing to direct-play. The previous implementation only checked whether the source container was listed in `directPlayProfiles`, ignoring this bitrate ceiling entirely.

**What happened in practice:** A FLAC at 800 kbps would return `canDirectPlay: true` even with `maxAudioBitrate: 192000`. Symfonium obeyed and called `stream?format=raw` — playing the original file unmodified on 4G instead of a transcoded 192 kbps stream.

**The fix:** `canDirectPlay` is now also `false` when `sourceBitrate × 1000 > maxAudioBitrate`. The `transcodeReason` field includes `AudioBitrateNotAllowed` in that case. Symfonium will now receive `canDirectPlay: false` / `canTranscode: true` and call `getTranscodeStream` to receive the opus/mp3 stream at the configured bitrate.
