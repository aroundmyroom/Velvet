# Velvet v0.6.1 — One-command install for Proxmox LXC and Incus

Velvet now runs directly inside an LXC container on Proxmox VE, or inside an
Incus container, with no Docker involved. One command creates the container
and installs Velvet into it; the same command, run again later, updates it.

## One line, both platforms

On a Proxmox VE host shell, or any host with the `incus` CLI already set up:

```shell
bash -c "$(curl -fsSL https://raw.githubusercontent.com/aroundmyroom/Velvet/main/contrib/lxc/ct/velvet.sh)"
```

It walks through the usual container questions — ID, hostname, disk, CPU,
RAM, storage pool, network — with a default-vs-advanced screen and a
verbose/non-verbose toggle for the install log, the same style used across
that ecosystem's other app installers. It automatically detects whether it's
running on Proxmox VE or an Incus host and uses the matching backend, so
there's one command to remember either way.

After the generic questions it asks a handful of Velvet-specific ones, each
skippable with Enter and settable later from the admin UI instead:

- where your music library lives on the host, bind-mounted read-write into
  the container;
- an admin username and password — leave blank to start in open mode;
- whether to also add a Radio Recordings, YouTube downloads, or Audiobooks
  folder.

It finishes by printing the URL to open.

## Updating

Run the exact same line again, pointed at the same container. It's detected
automatically and updated instead of creating a second one. The update
prefers going through Velvet's own [Admin → Updates](../docs/updates.md) API
— added in v0.6.0, the identical code path as pressing the button there —
and falls back to a direct `git fetch` + `npm install` if the app isn't
reachable yet.

## Also works with no Proxmox or Incus at all

The part that actually installs Velvet is its own, independent script with
no dependency on either platform:

```shell
curl -fsSL https://raw.githubusercontent.com/aroundmyroom/Velvet/main/contrib/shared/velvet-install.sh -o /tmp/velvet-install.sh
chmod +x /tmp/velvet-install.sh
/tmp/velvet-install.sh --mode install --music-dir /music --admin-user admin --admin-pass 'change-me'
```

It installs Node.js, clones a release tag, runs `npm install`, and sets up
the same `systemd` service [`docs/install.md`](../docs/install.md) has
always documented for a bare-metal install — so this is also simply the
fastest way to do that install by hand, container or not. Add `--dry-run` to
see exactly what it would do first, or `--help` for every option.

## One thing worth knowing: music-folder permissions

LXC and Incus containers bind-mount a host directory directly. An
**unprivileged** container (the safer default) remaps UIDs, so the `velvet`
user inside won't automatically see your host file ownership the way it
looks on the host — a **privileged** container avoids that at a small cost
to isolation. The wizard's quick defaults assume privileged; the full
tradeoff and the unprivileged setup steps are in
[`docs/lxc-incus.md`](../docs/lxc-incus.md#music-library-permissions).

## Status

This is new. It has been checked with dry-run simulations against every
option, static analysis, and automated tests, but — unlike the Docker and
bare-metal paths — hasn't yet accumulated real-world mileage across the
range of Proxmox and Incus setups out there. If something about your setup
trips it up, a report is genuinely useful.
