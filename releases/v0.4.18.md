# v0.4.18 — Server Listen Error Handling

## What's new

### Silent crash on port bind failure — fixed

`server.on('error')` was missing from Velvet's startup. When the port was already in use, or the bind address was unavailable, the server emitted an unhandled `error` event — the process crashed and the log ended abruptly with no explanation. The actual cause was invisible.

Now Velvet logs a clear, actionable message before exiting:

| Error code | Message |
|---|---|
| `EADDRINUSE` | Port X is already in use — stop whatever is bound to it or set a different port in your config |
| `EADDRNOTAVAIL` / `EAFNOSUPPORT` | Address not available on this host — try `"address": "0.0.0.0"` |
| `EACCES` | Permission denied — ports below 1024 require elevated privileges |

**IPv6 fallback:** Velvet defaults to binding `::` (IPv6 wildcard). On hosts where IPv6 is disabled (common in some Docker setups and VMs), this fails. Velvet now transparently retries once on `0.0.0.0` rather than failing to boot.

### TLS handshake abort noise — suppressed

The journal no longer fills up with:

```
Client network socket disconnected before secure TLS connection was established
```

This is harmless noise from internet port scanners and bots connecting to the HTTPS port and dropping before completing the handshake. These errors are now caught and logged at `debug` level only.
