# Velvet v0.2.0 — Player experience overhaul

A wave of player UI/UX improvements — faster-feeling loads, clearer empty
states, a keyboard command palette, queue quality-of-life, and visual polish —
together with two reliability fixes (the queue surviving a full localStorage)
and a build change that makes deploys reach browsers without a version bump.

## Perceived performance & feedback

- **Skeleton loaders.** Slow views (Artists, Album Library, search, and the Home
  shelves) now show shimmer placeholders shaped like their result instead of a
  blank pane or a bare spinner.
- **Reduced-motion support.** Velvet honours the OS *"reduce motion"* setting — a
  single global rule neutralises every CSS animation/transition, and the
  auto-triggered JS animations (the Auto-DJ dice throw, the scrolling-title
  marquee) are skipped.
- **Keyboard focus ring.** A consistent `:focus-visible` outline appears on nav
  buttons, icon buttons, rows, cards and sliders during keyboard navigation — and
  never for mouse/touch.
- **Stacking toasts.** Toasts stack instead of overwriting one another, announce
  to screen readers, and can carry an action (e.g. **Retry** on a failed
  add-to-playlist, which now confirms instantly and reconciles in the background).

## Empty states & onboarding

- **Clearer empty states.** A consistent illustrated placeholder (icon + title +
  message + a one-tap action) replaces bare one-liners for an empty queue, an
  empty playlist, no starred songs, and zero search results — each offering a
  relevant next step.
- **First-run tip.** A quiet, dismissible strip on Home points newcomers at the
  `?` keyboard-shortcut overlay and Auto-DJ. It appears once.

## Command palette

- **`Ctrl`/`Cmd` + `K`.** A fast fuzzy launcher: type to filter, arrow-keys to
  move, Enter to run, Esc to close. Jump to any sidebar view or run a transport
  action (play/pause, next, previous, shuffle, repeat, equalizer, shortcuts help)
  without reaching for the mouse. It is announced as a dialog with a listbox and
  skips its entrance animation under *reduce motion*.

## Queue quality-of-life & visual delight

- **Jump to now playing.** A queue-header button re-centres the list on the
  current track after you've scrolled away.
- **Drag drop-indicator.** Dragging a queue item shows a precise insertion line at
  the exact spot it will land.
- **Buffered-range indicator.** The progress bars show a faint bar that fills
  ahead of the playhead as audio buffers (hidden for live radio).
- **Soft view cross-fade.** Switching views fades the content in instead of
  snapping (disabled under *reduce motion*).

## Reliability fixes

- **The queue now survives a refresh even when localStorage is full.** A stale,
  pre-cap value (an old multi-MB Auto-DJ ignore list) could fill the browser's
  ~5 MB quota, after which the queue write silently failed and the queue was lost
  on reload. A boot-time sanitizer drops any oversized localStorage value (the
  server reseeds), `persistQueue` reclaims that space and retries, and fresh
  playback now clears the persisted ignore list rather than leaving it behind.
- **Auto-DJ no longer floods the console with `QuotaExceededError`** — its
  recently-played memory is capped to a rolling window and every write is
  fail-safe.

## Tooling

- **Content-hash cache-busters.** Webapp asset URLs are stamped
  `…?v=<version>-<hash>`, where the hash tracks each file's content — so a deploy
  reaches browsers as soon as a file changes, without waiting for a version bump.
  The hash is deterministic, so the version-sync CI gate still passes.
