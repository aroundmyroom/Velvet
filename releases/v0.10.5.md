# Velvet v0.10.5 — Similar artists without Last.fm

## Why

From 1 December 2026 a Last.fm API key only works while its owner pays for
Last.fm Pro. Velvet used Last.fm for every similar-artist list: Auto-DJ's
similar mode, the similar-artist chips on artist pages and in Playing Now, the
Home shelves *Because you listened to*, the AI DJ and Subsonic top tracks.
This release lets you choose where those lists come from.

## Choose your source

Under **Admin panel → Similar artists** you pick exactly one source:

| Source | Account | What you get |
|---|---|---|
| **ListenBrainz** (default) | none | Up to 100 similar artists with a score |
| **TIDAL** | free developer app (Client ID + Secret) | A ranked list, no score |
| **Last.fm** | API key, needs Last.fm Pro from 1 December | Up to 100 with a score, as before |
| **Off** | — | No similar artists |

- **ListenBrainz** works with MusicBrainz artist IDs. Velvet takes them from
  your files where AcoustID or the MusicBrainz search matched them, and
  otherwise looks the name up at MusicBrainz once and remembers it.
  Niche artists come out especially well (Klinik → Nitzer Ebb, Suicide
  Commando, Front Line Assembly). Very big names drift a little towards
  general pop.
- **A Test box** shows the top 25 for any artist, with score and whether each
  one is in your library. If the source doesn't know the artist, the box says
  so instead of showing an empty list.
- **Clear stored answers** empties the store, and switching source takes
  effect immediately.

We also looked at Deezer, Spotify, Apple Music, TasteDive and music-map, and
rejected them. `docs/similar-artists.md` explains why, how to set up each
source, and how to troubleshoot.

## Better matching to your library

Results that carry MusicBrainz IDs now match your library by ID as well as by
name. An ID only counts for a library artist when most of that artist's files
carry it, so a few wrongly tagged files can't pull in unrelated artists.

## Answers are kept

Similar-artist answers are stored in the database for 30 days. A restart, or
an outage at the source, no longer leaves Auto-DJ without similar artists.

## Subsonic top tracks

`getTopSongs` now blends Velvet's own play counts with ListenBrainz's most
played recordings of the artist. ListenBrainz needs a user token for this: the
one on the Similar artists page, or else the token of a user who connected
ListenBrainz for scrobbling. With Last.fm as the source, Last.fm's top tracks
are used as before.

## Clear about the source

Every similar-artists answer names its source. The browser console shows
`[Auto-DJ] ListenBrainz similar to "…"` instead of always saying Last.fm.

## Still on Last.fm

These still need a Last.fm key, and so Last.fm Pro after 1 December:
scrobbling to Last.fm, the artist bio, the Genre Enricher's Last.fm source,
and a last fallback in Subsonic `getSimilarSongs`. To keep scrobbling to other
services without Pro, use multi-scrobbler (v0.10.4).

## Emptying the queue

The bin in the queue panel now empties the whole queue in one click and stops
playback. Before, it kept the playing song, and removing that song took two
more clicks. The undo button next to the bin brings the queue back and
continues where it was. In a room the current song stays, because the room's
queue is shared. Thanks to Stéphane B. for the report.

## Upgrade notes

- **Existing installs start on ListenBrainz**, because that is the default
  source. To keep the old lists while your key still works, choose Last.fm
  under **Admin panel → Similar artists**.
- New database table `similar_cache` and a new index on `files.mb_artist_id`,
  both created automatically on start.
- New config section `similarArtists`.
- A hard refresh (Ctrl+F5) loads the new version.
