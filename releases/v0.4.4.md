# v0.4.4

Two fixes: Essentia BPM/key analysis now auto-starts after scan (was never triggered), and the Transcoding admin panel now shows readable status instead of raw `true`/`false`.

## Fixed: Essentia BPM/key auto-start missing from post-scan pipeline

After a library scan finished, AcoustID fingerprinting, ReplayGain, and AcousticBrainz lookups were all queued automatically — but **Essentia** (local BPM + musical key analysis) was never auto-started. It could only be launched manually from the Admin UI.

The missing `_tryEssentiaAutoStart` hook is now registered with `onEveryScanEnd`, using the same pattern as the other post-scan workers:

- **90 s boot delay** — lets AcoustID (15 s) and ReplayGain (60 s) settle before Essentia claims CPU
- **Deferred start if scan still running** — won't block or race an in-progress scan
- **< 500 file threshold** — on very large libraries the auto-start is skipped and a log message is written; an admin decision via the BPM Workshop panel is more appropriate for big backlogs

## Fixed: Transcoding admin panel showed raw `true`/`false` for FFmpeg status

The "FFmpeg Downloaded" row displayed the raw server boolean, which users interpreted as a config flag they needed to flip manually. It now shows **Ready** / **Not ready** (NL: Gereed / Niet gereed).

The **Download** button is also relabelled to **Verify / Download** to clarify that under Docker the binary is pre-installed in the image — clicking it verifies the existing binary rather than downloading it from the internet.
