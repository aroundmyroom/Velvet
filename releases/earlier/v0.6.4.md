# Velvet v0.6.4 — Proxmox LXC / Incus: verify the NFS/SMB share up front

A direct follow-up to v0.6.3's NFS/SMB options: can the share actually be
mounted, checked before the container exists rather than after.

## A real mount test, not just a format check

Right after you enter an NFS or SMB share's details, the wizard now attempts
a real tentative mount — on the Proxmox or Incus host itself, read-only,
then unmounted — before the container is created. A format check
(`server:/export`, `//server/share`) only catches typos. This also catches
an unreachable server, an export that doesn't allow this host, or a wrong
SMB password, all before any time is spent creating and configuring a
container.

`nfs-common`/`cifs-utils` are installed on the host automatically if
missing — the same client packages an NFS/CIFS-backed Proxmox storage pool
would already need. On non-Debian hosts without `apt-get` this fails closed
with a clear message rather than guessing at a package manager.

## If the test fails

Three choices, not a dead end:

- **Try different details** — maybe a typo, a wrong password, or the wrong
  export path.
- **Proceed anyway, unverified** — the host and the eventual container can
  genuinely see the network differently (same server, different VLAN is a
  real case), so a host-side failure isn't always decisive. The real mount
  is still attempted inside the container once it's created, same as
  before.
- **Skip for now** — set the library up later from the admin UI instead.

## Verified for real

Both test paths were run here against an unreachable test address rather
than just reading the code: each failed within a bounded time (10-14
seconds, not an indefinite hang), returned cleanly, and left no leftover
temp files behind. The package auto-install path was exercised live too.

[`docs/lxc-incus.md`](../docs/lxc-incus.md) documents the new step and the
three-way choice on failure.
