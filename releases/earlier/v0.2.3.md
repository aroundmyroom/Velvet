# Velvet v0.2.3 — Recently-added calendar-day view, scan-errors i18n fix, Auto-DJ loop fix

Three targeted fixes shipping together.

## Recently Added — calendar-day CTE

The "Recently Added" endpoint now groups tracks by *calendar day* rather than
returning the N most recently timestamped files.

Previously, a bulk import of 500 albums in a single session would fill the
entire Recently Added view with tracks from that one session, pushing everything
else out. The new query uses a CTE to find the N most recent **distinct calendar
days** on which tracks were added, then returns all tracks added on those days —
so a bulk import still appears as one day in the list, and earlier days remain
visible.

## Admin — scan errors i18n pluralisation fix

The scan-errors table footer translation call was missing the `count` parameter
required for plural forms in several locales. The footer count text could show a
raw key or the singular form regardless of how many errors were listed. Fixed by
passing `count: filteredErrors.length` alongside the existing `shown` and `total`
params.

## Auto-DJ — similar-artists loop fix

When Similar Artists mode is enabled and the library contains fewer than 10 tracks
from the artists Last.fm returns, Auto-DJ could loop over the same 2–3 songs
indefinitely.

**Root cause:** the server-side ignore list is capped at 50% of the candidate
pool. With a 3-song pool that cap allows only 1 song to be cooled at a time, so
the other 2 keep coming back. The widening fallback (`_noSimilarFallbacks`) never
triggered because the pool was non-empty.

**Fix:** a `MIN_SIMILAR_POOL = 10` threshold is checked after the similar-artist
steps. If the pool is below this threshold it is treated as empty, which forces
the fallback chain to widen to the full library. A catch-all handles the
no-BPM/no-key case where the existing BPM-gated fallback steps would not fire.
