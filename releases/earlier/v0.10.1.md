# Velvet v0.10.1 — Skins, and an Auto-DJ that keeps collaborations apart

## Skins

Give the web player your own look. A skin is one `skin.css` in its own folder;
Velvet loads it after its own stylesheet, so a skin only overrides what it
wants to change. Usually that is Velvet's colour variables (`--bg`,
`--primary`, `--t1` and friends); a skin can also restyle shapes and details.

- **Your own skins** go in `save/skins/<name>/skin.css`. They show up without a
  restart, and updates never touch them.
- **Users** pick a skin under User Settings → **Skin** (server default, none, or
  a skin). The choice follows them to other browsers.
- **Admins** set the default under Settings → User Interface → **Default Skin**.
- **One example ships with Velvet:** **goud**, black and gold, with a gold play
  button.

A skin is CSS only: it cannot run scripts or change what the player does. How to
write one, with the list of colour variables and the full example, is in
`docs/skins.md`.

## Auto-DJ keeps collaborations apart

Auto-DJ could play the same artist three times in a row when that artist turned
up in collaborations, for example "Armin van Buuren & AVIRA", then "Marco
Borsato, Armin van Buuren, Davina Michelle". Now:

- Comma- and semicolon-separated credits are split, so the artist cooldown
  recognises the same artist inside a collaboration, in the browser and on the
  server (rooms).
- The similar-artist lookup falls back to the main artist when a long credit
  has too few matches in your library.
- When every similar artist was played recently, Auto-DJ first widens to the
  rest of your library before it lets a recent artist back in.

## Smaller changes

- **Pair a Device** now mentions Home Assistant, which pairs the same way.

## API

- New: `POST /api/v1/admin/config/skin` sets the default skin.
- `GET /api/v1/ping` now also returns `skins` and `defaultSkin`.
- New config keys: `skin` and `storage.skinsDirectory` (default `save/skins`).

See `docs/API.md`.
