# Velvet v0.6.6 — Docs: explain the two harmless 404s at wizard startup

A documentation-only follow-up to v0.6.5, for something reported alongside
that crash: two `curl: (22) The requested URL returned error: 404` lines
printed right when the Proxmox LXC / Incus install wizard starts.

## What they are

Confirmed by directly reproducing the exact reported command with a full
execution trace, not by reading the source alone. The community-scripts
engine looks up an optional custom ASCII-art banner for the app it's
installing, from its own official catalog:

```
https://raw.githubusercontent.com/community-scripts/core/main/headers/ct/velvet
https://raw.githubusercontent.com/community-scripts/core/main/headers/ct/pve/velvet
```

That's a feature for apps listed in that catalog. Velvet isn't one, so both
requests 404 — and the trace shows the engine handling that completely
normally, falling straight through to the regular plain-text banner right
after. Nothing downstream depends on this lookup succeeding.

## What's fixed

Nothing — there was nothing broken in `ct/velvet.sh` to fix. The lookup URL
is hardcoded inside the upstream engine itself, not derived from anything a
third-party script controls, so there's no way to redirect or suppress it
from our side. The only way to make the two lines disappear entirely would
be contributing a header file to community-scripts' own catalog repository,
which is a separate, optional, later thing — not a bug fix.

[`docs/lxc-incus.md`](../docs/lxc-incus.md)'s troubleshooting table now
explains this directly, so it reads as expected rather than alarming.
