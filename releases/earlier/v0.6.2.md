# Velvet v0.6.2 — Fix the in-container update command from v0.6.1

A small but real fix to v0.6.1's Proxmox LXC / Incus install.

## What was wrong

Every Velvet container created by v0.6.1's install wizard gets a standard
`update` command on its `PATH`, the same convention every
[community-scripts](https://community-scripts.org) app container has —
written automatically during install, no extra setup needed. SSH or console
into the container and run `update` to pull the latest Velvet release.

That command would have failed. The update logic underneath it was written
assuming it always runs on the Proxmox or Incus host, so it wrapped every
step in `pct exec`/`incus exec`. In reality, `update` runs *inside* the
container itself — where neither `pct` nor `incus` exists at all. This was
caught by reading the actual community-scripts engine source and a real
shipped app's install script directly, rather than by someone hitting the
failure first.

## What's fixed

The update logic now runs entirely locally inside the container, matching
how every other app in that ecosystem does it. Re-running the host-side
one-liner against an existing container to update it — the other documented
way — was never affected by this bug; only the in-container `update` command
was broken.

[`docs/lxc-incus.md`](../docs/lxc-incus.md) now documents both ways to
update a container: re-running the host one-liner, or running `update`
inside the container directly.

## Also: the README was missing this entirely

v0.6.1 added the Proxmox LXC / Incus install path but never linked it from
`README.md`. It's now in the Quick Start guide links, the Installation
table, and the Documentation table.
