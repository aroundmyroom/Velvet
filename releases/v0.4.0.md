# v0.4.0

Auto-DJ redesign: hard-filter fallback chain replaced with soft/weighted batch scoring, plus a hard artist-repeat floor and a playback-stall fix that could silently halt Auto-DJ mid-session.

## Auto-DJ — soft-scoring architecture

Auto-DJ's next-song selection has been completely redesigned. The old model applied **hard filters** — BPM window, harmonic/key match, genre group, similar-artist list — and escalated through an ever-growing chain of fallback tiers whenever a combination proved too restrictive for a real library (which happened often: BPM + key + genre + similar-artist together can easily have zero matches in a smaller collection).

The new model:

1. Fetch a **broad batch** of candidates in one request (`POST /api/v1/db/random-songs` with `returnAll: true`) — scoped only to hard constraints that must always hold: selected collections/paths, minimum rating, the similar-artist list (when active), and the artist cooldown list.
2. Drop keyword-blocked and just-played tracks.
3. **Score every remaining candidate** on:
   - Similar-artist (Last.fm) rank — up to 35%
   - BPM continuity — up to 25%
   - Genre compatibility (+ your whitelist/blacklist) — up to 13%
   - Harmonic (Camelot wheel) mixing — up to 7%
   - Year/era continuity — 10% (fixed)
   - Artist diversity/cooldown — 10% (fixed)
4. Queue the single highest-scoring song.

When Last.fm has no similar-artist data for the current track, that 35% weight is redistributed into BPM/genre/harmonic instead of being wasted, so those signals become the primary basis for the pick.

Full design notes: `docs/autodj-scoring.md`.

### Fixed: small similar artists getting crowded out
When a similar-artist list is active, an artist with a large catalogue in your library could statistically dominate the candidate pool, so a well-tagged song from a thinly-represented similar artist might never even reach the scoring stage. The batch is now sampled per-artist first (up to 10 songs per similar artist) before the overall cap, guaranteeing every similar artist a fair shot.

### Fixed: same artist repeating within a handful of songs
The server's artist-cooldown fallback can legitimately drop the cooldown constraint entirely when the similar-artist pool is too narrow to satisfy both filters at once. Auto-DJ now also enforces a **hard floor client-side**: the last 3 played artists are never eligible for the next pick, no matter what the server returns — on top of the existing 15-song soft diversity scoring window.

### Fixed: Auto-DJ could silently stop advancing while Sonos kept playing
The browser's local (muted, used only to drive the waveform and the "song ended" trigger) audio element only recovered from network stalls on the `stalled` event. A slow buffer underrun — the far more common real-world cause of a stuck stream — fires `waiting` instead, which had no recovery handler at all. The element could then hang indefinitely: the waveform froze, no "ended" event ever fired, and Auto-DJ never queued a new song — while Sonos, which streams independently from the server, simply finished playing the current track on its own. `waiting` now triggers the same stall-recovery path as `stalled`.
