# v0.4.15

Implement `transcodeOffset` OpenSubsonic extension — true seeking in transcoded streams.

## Added: `transcodeOffset` extension

The `stream` endpoint now accepts `timeOffset` for music when transcoding is active. ffmpeg starts encoding from that position (`-ss <seconds>`), so seeking no longer requires restarting the entire stream from the beginning.

`transcodeOffset` is advertised in `getOpenSubsonicExtensions`. Clients like Tempus check for this extension to decide which media source to use: with `transcodeOffset` present, Tempus selects `TranscodingMediaSource` (proper seek support) instead of `ProgressiveMediaSource` (seek = restart + fast-forward). Symfonium similarly enables proper seek UX when this extension is present.

The `Content-Length` estimate is also adjusted to reflect the remaining duration after the offset, keeping the seekbar accurate after a seek.

The ffmpeg `-ss` support was already present in the transcoding engine — the `stream` endpoint simply was not reading the `timeOffset` parameter.
