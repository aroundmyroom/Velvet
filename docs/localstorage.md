# Velvet — localStorage Key Reference

Most keys are written and read by the player, `webapp/app.js`. A few come from
shared scripts (`webapp/assets/js/i18n.js`, `webapp/assets/js/api.js`), the
admin panel, and the other web apps — see **Keys outside the player** below.

Most user preferences are also copied to the server (`POST /api/v1/user/settings`,
see `_collectPrefs()` in `webapp/app.js`) so they follow the user to another
browser. localStorage is the local copy.

> `webapp/app.js` and `webapp/mobile/` are being reworked (i18n). Key names
> below match the code on 2026-11-15; re-check with
> `grep -o "localStorage\.[a-zA-Z]*Item([^)]*" webapp/app.js | sort -u` if in doubt.

## Scoping rules

The app operates in two modes:

| Mode | `S.username` | Key suffix |
|---|---|---|
| **No-auth** (server has no users configured) | `''` (empty string) | `_` (trailing underscore, e.g. `ms2_vol_`) |
| **Authenticated** | `'alice'` | `_alice` (e.g. `ms2_vol_alice`) |

### Helpers

```js
// For user-preference keys (audio, UI, playback settings):
function _uKey(k) { return `ms2_${k}_${S.username || ''}`; }

// For Auto-DJ keys:
function _djKey(k) { return `ms2_dj_${k}_${S.username || ''}`; }

// For the play queue and its playing flag:
function _queueKey()   { return `ms2_queue_${S.username}`; }
function _playingKey() { return `ms2_playing_${S.username}`; }
```

Keys generated by `_uKey` and `_djKey` include the username suffix even when the server runs with no auth (`username = ''`), so settings from a no-auth session are never clobbered when a user later logs in.
The queue is only persisted when a username exists (`persistQueue()` returns early otherwise).

Some keys are built inline with the same `ms2_<name>_<username>` pattern instead of through `_uKey` (for example `ms2_time_flipped_`, `ms2_pinned_view_`, `ms2_album_click_mode_`, `ms2_home_order_`).

## Global keys (not user-scoped)

| Key | Type | Description |
|---|---|---|
| `ms2_server_id` | UUID string | Server instance identity — set on first visit; mismatch triggers `localStorage.clear()` + reload |
| `ms2_browser_id` | random string | Stable per-browser id; tells the server-side queue copy which browser saved it |
| `ms2_token` | string | JWT access token — cleared on logout |
| `token` | string | Mirror of the token for the admin panel and `assets/js/api.js` |
| `ms2_user` | string | Username matching the token payload |
| `ms2_logged_out` | `'1'` / absent | Set on explicit logout; prevents cookie-auth re-entry |
| `ms2_sidebar_collapsed` | `'1'` / `'0'` | Sidebar collapsed to the icon-only rail |
| `ms2_nav_collapsed` | JSON array | Sidebar sections the user folded closed |
| `ms2_ls_clean_v1` | `'1'` | One-time cleanup marker (old `wf:` waveform keys and bloated artist history removed) |
| `ms2_dbg_boot` | `'1'` / absent | Opt-in boot debug logging, set by hand in the console |
| `velvet.seen.intro` | `'1'` / absent | The first-run tip strip on Home was dismissed |

## Lifecycle

| Event | Action |
|---|---|
| **Page load (before login)** | IIFE fetches `/api/v1/ping/public`; compares `ms2_server_id` to server `instanceId`. Mismatch → `localStorage.clear()` + `location.reload()`. First visit → sets `ms2_server_id`. |
| Login (`tryLogin`, `tryPasskeyLogin`; both finish in `_completeLogin`) | `ms2_token` + `ms2_user` (and the `token` mirror) written; `ms2_logged_out` removed. A passkey login loads the same flags, server settings and language as a password login |
| Session restore (`checkSession` token path) | `ms2_user` read; DJ + queue keys resolved |
| Session restore (cookie/no-auth path) | `ms2_user` read (may be empty); all `_uKey` → `ms2_*_` |
| `showApp()` | Queue, Auto-DJ ignore list, sleep timer, and Auto-DJ toggle restored |
| Logout | `ms2_token` + `ms2_user` + `token` removed; `ms2_logged_out` = `'1'`; cookie expired; `{ type: 'logout' }` posted on the `BroadcastChannel` `velvet`, so every other open player tab pauses, drops its token and returns to the login screen |

## Multi-user behaviour on a shared browser

Because every user-preference key is suffixed with the username, two users (`alice` and `bob`) on the same browser maintain completely independent:
- volume, balance, EQ, crossfade
- Auto-DJ sources, rating filter, and play-history
- theme, visualiser mode, spectrum style, transcoding settings
- sleep timer and Auto-DJ on/off state

A no-auth server still gets its own isolated slot (suffix `_`).

---

## Multi-server isolation

localStorage is scoped by the browser to the page origin (protocol + hostname + port). Without additional protection, two Velvet servers behind the same origin — or a reinstall of the same server — would share all `ms2_*` keys, including `ms2_token` and `ms2_user`.

**The `ms2_server_id` guard solves this**: on every page load the app fetches `GET /api/v1/ping/public` (no auth) and compares the returned `instanceId` to the stored `ms2_server_id`. A mismatch means a different or reinstalled server is now at this origin — `localStorage.clear()` is called and the page reloads cleanly. The check runs in parallel with the rest of page start-up.

The `instanceId` is generated once by the server (`crypto.randomUUID()`) and saved in the config file (`save/conf/default.json`). It survives server restarts but is regenerated on a clean install.
