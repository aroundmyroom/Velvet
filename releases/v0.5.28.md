# Velvet v0.5.28 — Reverse-Proxy Login, Pair a Device, and Three Fixes

The headline is two new ways to sign in without typing a password on an
awkward device, plus a handful of fixes picked up along the way: quieter
logs, a Unicode bug in artist search, and a dead-end when switching a phone
to the desktop site.

## Reverse-proxy login (SSO)

A reverse proxy — or an auth layer sitting in front of it, such as Authelia
or Authentik — can now sign users in directly by asserting a trusted header,
instead of everyone typing a username and password into Velvet's own form.
Velvet's own login form keeps working the whole time; this is an additional
way in, not a replacement. It works behind any reverse proxy that can be
configured to forward a header — Nginx Proxy Manager, Traefik and Caddy all
have worked examples in the new `docs/auth-reverse-proxy.md`.

The header is only trusted from an admin-configured allowlist of proxy
IPs/CIDR ranges, checked against the actual TCP connection rather than a
spoofable `X-Forwarded-For` header, plus an optional shared secret that
closes the remaining gap on a shared Docker network. Configure it under
Admin → Settings.

## Pair a Device

Devices with an awkward keyboard — a Samsung TV remote, a kiosk — can now
sign in by showing a short code that's approved from an already-logged-in
phone or browser, instead of typing a password with a D-pad. Codes are
single-use and expire after 5 minutes.

- The **Samsung TV app**'s sign-in screen has a "Pair with phone instead"
  option.
- The **web player**'s User Settings has an "Approve a Device" section for
  approving another device's code.
- The **mobile site** can be on either side of a pairing: approve another
  device from the You screen, or sign this phone in via a code from its own
  connect screen — useful if typing a password on the phone itself is what
  you're trying to avoid.

## Fixed: no way back from the desktop site on a phone

Switching a phone to the desktop site is sticky by design — the choice
persists across visits — but there was no way back once you'd used it; the
option to switch only ever existed on the mobile side. Both directions now
exist: "Use mobile site" from the desktop login screen and User Settings,
alongside the existing "Use desktop site" option on the mobile site.

## Fixed: refused requests no longer appear in the log as server errors

A request Velvet refuses before any feature runs — invalid JSON, a body over
the size limit, a web address with broken percent-escapes — was answered
correctly but logged as a server error with a full stack trace, which could
fill the log with noise and occasionally echo part of what was sent. These
are now a single warning line naming the method, path and reason, with
nothing from the request body.

## Fixed: admin artist-image search failed for artist names with accented capitals

Artists whose stored name had an accented capital letter (e.g. "BLØF") failed
every case-insensitive name lookup — the admin Discogs/TheAudioDB image
search, and anything else that compares lowercased artist names, reported
"not found" even though the artist was in the library. SQLite's built-in
lowercase/uppercase functions only handle plain ASCII letters; that's now
fixed everywhere artist names are compared. Separately, TheAudioDB's shared
test key that background image lookups depend on had stopped working —
switched to their other public key, with an optional override if it's ever
disabled too.

## Upgrade note

Restart the server after upgrading. Reload the player and admin panel in
your browser to pick up the new User Settings and Admin → Settings sections.
